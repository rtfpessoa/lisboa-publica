## Changes and acceptance

1. F1: two fail-fast slots shared by expensive read endpoints (trips, arrivals, metrics, history, fleet, traffic, rankings, operator coverage); 15-second operation contexts cover authentication, pool acquisition, SQL and response preparation. Return structured 503 for busy/timeout, retain cancellation. Use a small read-only transaction helper for public historical queries, with SET LOCAL statement_timeout=15s and rollback/release after reads. Do not change pool defaults, migrations, restore or collector SQL settings. Validate local Postgres and local Cockroach compatibility if available; an untested Cockroach path is a deployment gate. Context-aware schedule loops, reject unknown stops and incompatible operator filters before processing, query only a stop's provider and avoid discarded trips on arrivals. HTTP arrivals/status serve cached Metro data from the existing five-second collector; they never wait on Metro refresh/publication locks. Cached normal status older than90 seconds or without CheckedAt is reported unavailable with no normal-line assertions; this response does not mutate cache state. Pinned pages retain their captured revision. Bound schedule result allocation at 100,000 across selected providers and ask callers to narrow a window if exceeded; preserve accurate pagination within the bound. Historical grouped lists also have SQL LIMIT100001 and a 100,000 scanned-row/result ceiling; reject oversized requests rather than silently truncate, with exact pagination below the bound. No query framework or separate read pool. Local regression verifies cancellation, unknown-stop rejection, parent stops, revision/window pagination, admission/release and SQL cancellation. Query optimization beyond these bounds is deferred until measurement.
2. F4: route only logout and owner-scoped revocation through a dedicated cleanup write path using existing headroom up to 5 GB. Ordinary credential issuance remains capped at 4.5 GB. Measurements remain fail-closed: failure/full ceiling reports unsuccessful server invalidation. For exact-origin POST logout, clear the browser cookie in middleware before DB-dependent authentication, and in the handler. Retain authentication/Origin enforcement and report failed server invalidation, including auth lookup failure; do not return false success. No unlimited emergency write or hard cluster-cap claim. Provide a restricted operator recovery runbook for measurement/DB failure. Test 4.5 GB success, issuance rejection, 5 GB/measurement failure rejection and cookie clearing; preserve owner/Origin controls.
3. F2: serialize key count and insertion under the existing single-process write lock; split the existing exec wrapper only enough to avoid recursive locking. No distributed lock framework. Deployment is one app process; document multi-instance deployment requires a database-atomic quota. Concurrent isolated-schema test starts with 19 active keys and proves exactly one of eight creations succeeds, scopes/ownership unchanged.
4. F3: subtract-before-add ZIP budget check, entry-count cap (256) and duplicate normalized-name rejection. Preserve existing 512 MiB/5M row bounds. Eight available local official archives have 10–14 entries and no duplicate normalized names. Validate full parsing locally with these fixtures. Defer new CSV field/record limits: physical-line limits alone do not bound multiline quoted records, and the confirmed overflow fix does not require a new CSV parser. Existing per-file byte/row limits remain; pathological record allocation is a documented residual risk.
5. S2: require archive initial HTTPS/443/no URL credentials; shared redirects preserve the initial HTTPS hostname and effective port and forbid credentials, explicitly retaining the fixed Metro API port8243; preserve at most two redirects and budget accounting. Apply archive initial policy explicitly. Use fake/local TLS servers only; no private-address probing. Do not broaden to arbitrary URL input or IP filtering for fixed trusted hosts.
6. H1: application headers frame-ancestors 'none', X-Frame-Options DENY, Permissions-Policy disabling unused camera/microphone and retaining self geolocation, HTTPS-origin HSTS max-age 1 year without subdomains/preload. Do not deploy a broad script/style CSP without browser validation. Tests check header behavior and existing UI/map flows.
7. F5: choose a current official Caddy artifact or build the same version using patched Go; verify exact ARM64 binary build info and local vulnerability scan. Prefer unchanged Caddy feature version to reduce shared-host compatibility risk. Prepare a digest-pinned compose override and read-only validation commands preserving active mounts/networks/ports. Record authorization needed, all-site TLS checks and rollback (rollback to vulnerable artifact is temporary recovery only). No production pull/restart/config change in this task without explicit rollout authorization.
