# CP coverage, visible metrics and official route overlays

Main agent owns planning, implementation, testing, fixes and acceptance. Independent plan/final reviews use the existing real quasar-alpha reviewers at xhigh.

Evidence: [CP coverage](research/CP-COVERAGE.md), [official geometry](research/ROUTE-OVERLAYS.md), production browser/API observation on 2026-09-26. CP empty responses originate upstream despite successful collection and valid timetables. Current charts receive history; disconnected points separated by null require visible markers. Recharts already renders a single-point series, so that alone is not a defect. Moving end timestamps create new query keys every 30 seconds, clearing values during requests. Initial history is unavailable until a five-minute bucket closes plus 90 seconds.

1. Reproduce delayed-refresh disappearance and isolated chart points with browser regressions. Keep stable query identities for the same operators/route/day/period, refreshing the moving request window separately. Never carry values across changed filters. Fetch chart history when a trend is opened from the traffic view. Show loading, error, no observations and collection delay distinctly. Show single-point dots for both speed and volume. Current reported/estimated counts and valid sampled speed come from fresh local vehicle positions, independently of closed historical buckets; historical means remain historical. Label exact commercial speed/completed trips unavailable.
2. Preserve CP schedules and successful-source health; explicitly show “Sem observações atuais” for an empty fresh feed and explain partial coverage, without inferring no trains operate or inventing positions.
3. Add `/api/v1/route-shapes`, operator/route filters, pagination and frozen cache revision, scope `read:transit`, existing public and key rate limits. Generate both clients/interfaces from the one OpenAPI contract. Shape variants contain IDs, operator/route, direction, headsign, plan/source timestamp, official longitude/latitude geometry and line color. Retain unique route/shape/direction variants from current GTFS, deterministic ordering; existing route detail keeps a deterministic representative shape for compatibility.
4. CM geometry: discover the four active official agency plans via the existing Hub plans fetch; sequential bounded archive downloads, lightweight routes/trips/shapes parsing only, map GTFS line_id to existing CM line IDs. No thousands-of-pattern requests, no new collector. Geometry IDs include CM agency and plan before deduplication. Geometry failure or bounded cache admission rejection preserves previous geometry while marking its availability/staleness separately; static route catalog must still update. Existing four GTFS providers retain all referenced shapes. Bound geometry volume and simplify official vertices with a declared 2-metre maximum perpendicular deviation (local metre projection), retaining endpoints, only after measurement; preserve route endpoints and variants, never synthesize paths from stops. Measure gzip cache allocation and memory against 128MiB write reservation and the 1280MiB container, retaining 5GB storage guard and 900 upstream requests/rolling minute.
5. Map layer panel: independent “Linhas de metro” / “Percursos de autocarro” checkboxes, initially OFF as confirmed by user; selected operators only, honor selected route. Fetch paginated local geometry only when requested, render lines below stops/vehicles with operator/line colors and selected-route highlight. Display loading/partial/missing geometry explicitly. No UI provider requests. Keep responsive controls.
6. Verify Go race tests with PG and CRDB, contract generation, TS build, targeted browser regressions plus dashboard suites; real official feeds and cache encoding/memory measurement. Independent final review with research, changes and test results; fix blockers and repeat until acceptance. Normal Maat gate, atomic commit/push and deploy using the authorized existing Compose/Caddy/external DB setup. Observe one collector, memory, CP state, nonempty actual curves and both overlay types after full static refresh.

Out of scope: new providers, authentication requirement, complete fleet inventory, exact commercial speed, routing/journey planning, geographic database extensions, historical geometry snapshots, changed retention or storage caps.

Pre-fix browser evidence: all three targeted regressions fail (fresh live speed vs null historical mean; refresh clears count; two valid speed points separated by null render zero markers). Single-point series alone already worked.

Independent plan review: existing real quasar-alpha/xhigh reviewer recommended acceptance, no blockers. CM IDs/join verified directly; bounded parsing/cache fallback retained. Explicit conditional response cache limited to1MiB per body so four added archives do not accumulate in memory between six-hour static refreshes.
