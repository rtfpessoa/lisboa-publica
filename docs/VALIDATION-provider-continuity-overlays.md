# Provider continuity and rail/ferry overlay validation

Date: 2026-09-26. Status: local implementation accepted after independent final review and main-agent requirement verification. No commit, push or deployment for this change has occurred.

## Implemented behavior

All eight providers use original-observation-time last-known retention. Omitted, stale and unverified positions are excluded immediately from current operation metrics; they become inactive after five minutes and expire after one hour. New observations recover normally, while equal/regressed reports cannot create new history or bridge movement gaps. The display cap is 500 previous positions per provider with an explicit truncation notice. The collector ledger is capped at 2,000 IDs, with a conservative replay floor after eviction/restoration. History-only sample arrays and replay ledgers are excluded from archived display revisions. The pagination version cap is 64 with the existing maximum five-minute age and 410/reload behavior; high publication churn can expire a token earlier. Static replacement preserves the original frozen-page behavior within the bounded revision cache. Large static arrays are streamed into the existing gzip JSON wire format; exact keys, omission/null/empty semantics, and legacy decoder compatibility are tested.

The single OpenAPI contract generates both Go and TypeScript. Current/unknown/partial live totals share the backend projection; the UI treats failed vehicle or operator-status reads conservatively even when cached data remains. Current rows also carry their original one-hour expiry so a disconnected browser can remove cached positions.

Train and ferry overlays use published service shapes through the existing route-shapes API. All four controls default on, geometry follows selected operators, and Metro remains the only initially selected operator. Geometry persists independently of live availability. Mode signatures prevent re-sending unchanged geometry on live operator refresh. Optional shape syntax/variant failures preserve useful static routes and schedules, while archive integrity/resource failures remain fatal.

## Resource gate and remaining verification

The opt-in, non-race resource test uses actual current static feeds, 721 five-second ticks (one hour), and exactly 1,000 fresh unique source rows per tick per operator, independent of retention caps. It saturates the bounded previous-position display, collector replay ledger, pagination revisions and 20,000 pending history entries; checks encoded cache admission; and now publishes a complete static refresh into the cache while old revisions remain. No remote API or production database participates. GOMEMLIMIT remains 768 MiB and GOMAXPROCS remains 2. The required peak RSS ceiling is 1,073,741,824 bytes (1,024 MiB), below the existing 1,280 MiB container ceiling.

Earlier retention measurements failed: 256 revisions/1,000 display rows reached 1,273,249,792 bytes; 128 revisions without archived-ledger removal reached 1,144,389,632. Removing archived ledgers produced one 1,062,912,000-byte run, but its repeat reached 1,099,251,712 and therefore failed acceptance. A 96-revision/500-display run reached 1,076,805,632 and also failed; being close to the ceiling is not a pass. These early static-overlap probes parsed refreshed feeds without publishing every replacement; the final stronger probe replaces all static providers and measures the retained overlap. The stronger replacement-retaining probe reached 1,855,012,864 bytes at 96 revisions and 1,810,038,784 at 64, exposing complete old networks retained across a full static refresh. The main agent tested expiring old tokens on static replacement, which alone still reached 1,777,434,624 bytes. Inspection then identified whole-timetable JSON encoding buffers as the peak-amplifying cause; streaming individual large-array elements into the existing gzip cache corrected the peak. A static-token invalidation prototype plus streaming passed, but was not needed: streaming with the original static paging behavior passed twice at **1,050,886,144** and **1,064,763,392** bytes (about **1,002.2 and 1,015.4 MiB**), retaining all 64 revisions after the full refresh. The prototype token invalidation and its changed test expectations were removed. The final actual-workspace confirmation passed at **1,020,477,440 bytes (973.2 MiB)**, with all eight static providers, 64 retained versions, 1,000 source/500 previous/2,000 ledger entries per operator and 20,000 pending history entries. All three original-paging runs meet the hard gate; production limits are unchanged. No production resource limits have been increased.

## Limits and rollout

This is local validation on macOS, including isolated local PostgreSQL and CockroachDB. It is not a production Linux RSS guarantee or a deployment acceptance. Upstream partner causes and future availability remain outside application control. Published static shapes do not establish complete physical-network coverage. Bounded retention may omit older eligible positions and conservatively suppress replay-risk history during extreme churn; this is explicit rather than fabricated completeness. Existing guarded history-write partial-loss semantics are preserved.

The public UI, provider request budgets, five-second refresh, thirty-day compact history, five-billion-byte application storage guard, authentication/API-key scopes and existing security controls remain unchanged. There are no new tables, queues, upstream integrations or production configuration changes. Commit/push/deployment remain a subsequent authorized stage with rollback and bounded post-deployment checks.
