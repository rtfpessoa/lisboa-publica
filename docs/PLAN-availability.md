## Diagnosis and decisions

- Completed-trip percentage and operational frequency are intentionally unavailable: scheduled trips and sparse positions do not establish completed departures/arrivals. Mark unsupported controls visibly unavailable with a persistent explanation; never manufacture percentages or relabel schedules as actual frequency.
- Traffic, rankings, fleet, searches, arrivals and detail queries need distinct initial loading, background updating, errors and successful empty states. Preserve displayed values during same-filter refresh; never present prior-filter data as current.
- Operator availability must follow the view/window: live counts are not evidence of historical absence, and Metro estimates have no valid traffic speed. Gray unavailable operators with explicit contextual text while keeping selection usable to inspect schedules or other views. A single small paginated historical operator-coverage endpoint aggregates all operators' observed vehicle/speed/metadata counts in the selected interval and traffic hour/weekday filters; use existing immutable snapshot revision and read:history policy. Avoid eight independent historical requests.
- Fleet fields must come from verified published identities. Research already confirms identical Carris make/model strings and CM vehicles.txt in the same four already-downloaded geometry archives. Normalize duplicate manufacturer/model names; ingest that optional metadata without extra requests; preserve older metadata during partial refresh. Add only source-confirmed typology/propulsion fields with nullable generated schema, snapshot payloads and honest coverage. Depots/assignments remain explicitly unavailable unless primary evidence changes this.
- Polling intervals follow verified source freshness and limits, not quota saturation. Live/direct5s confirmed by research, heavy history/traffic SQL remains30s, metadata5min/static6h unchanged. Shared transport retains900 rolling/min, adds lower official CM per-second ceiling and origin Retry-After/exponential429/503 cooldown without immediate retries. Unknown limits remain documented and conservatively bounded.
- Faster memory publication must not multiply database cache writes: stage bounded five-second observations in the existing compact collector, commit cache/history no more often than30s per operator (except raw-history mode), preserving failed-transaction pending state, deduplication and all intervening distance/speed samples. Direct Metro memory refresh5s, durable cache30s. Retain sufficient live cache revisions for slow pagination and measure real warm-refresh memory before acceptance.

## Plan-review safeguards

Separate five-second polling, thirty-second durable publication and existing thirty-second provider-clock-skew constants; never tighten accepted source clock skew by changing polling. Source research: [limits](research/POLLING-LIMITS.md), [fleet fields](research/FLEET-FIELDS.md). Typology/propulsion remain published raw codes or strings with explicit labels; historical fields remain recorded snapshot metadata (no mutable current-static fallback).

Staging uses the existing collector under historyMu while publication holds PublishMu: accept every five-second observation exactly once, retain speed/distance in bounded pending buckets, do not close or acknowledge staged history until Save proposes and its transaction commits. Save failure retains all staged pending state; retry sees deduplicated observation timestamps. Pause clears closed pending state through the existing guard, stage rejects unavailable/paused collection, and memory caps remain20000entries. Focused tests must demonstrate multiple five-second observations totalled across an injected failed commit, later successful close and duplicate retry without loss/double count.

Increase retained immutable cache versions from24 to256 (about140s at nine publications/5s; versions still expire after5min). Static geometry remains shared across versions; measure full warm refresh plus settled memory. Test later vehicle/shape pages against a frozen revision after at least60s-equivalent faster publications, and ensure changedfilters do not inherit data.

The30s durability bound includes successful and failed source-health states for all operators and directMetro: memory publishes status immediately, durable attempts are scheduled no more often than30s even during upstream outages/database failures. A failed durable attempt keeps staged collector state for the next flush; only committed proposals replace collector state. History/coverage read committed snapshots only. Paused/unavailable stage does not grow memory, pending entry caps bound prolonged failure; existing pause cleanup remains authoritative. UI states first-bucket closure5min +90s +up to30s durableflush; live5s is collection cadence, not a freshness guarantee.
