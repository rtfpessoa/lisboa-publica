## Application changes, pending deployment

- **F1:** two shared fail-fast slots for expensive reads; 15-second contexts cover auth/pool/queries/work. Historical reads use read-only transactions with a local 15-second SQL timeout, preserving collector/migration/pool defaults. Schedule loops honor cancellation. HTTP arrivals/status read the cached Metro result maintained by the five-second collector and never wait on its refresh/publication locks. Cached normal service older than 90 seconds or missing CheckedAt is reported unavailable and its normal-line assertions are hidden, without mutating the cached revision. Stop/provider validation precedes schedule work and uses the requested immutable network; parent and direct Metro station IDs are recognized. Arrivals do not build discarded trips or scan other operators. Schedule/grouped historical results cap at 100,000, with accurate totals below the cap and explicit errors above it. Historical SQL limits returned grouped rows to 100,001. SQL aggregation itself can still cost work; time/concurrency controls apply. Timeouts/busy use structured 503, with Retry-After on busy responses. Provider quotas remain unchanged.
- **F4:** logout and owner-scoped revocation reserve measured cleanup headroom up to the existing 5 GB application ceiling. Issuance remains under 4.5 GB. Full ceiling/measurement failures remain fail-closed. Exact-origin POST logout clears the browser cookie before DB-dependent authentication can fail; server invalidation failure still returns an error. A cleared browser cookie does not invalidate a stolen server session.
- **F2:** the existing single-process write lock now encloses quota count and insertion. A 19-key fixture with eight concurrent creates yields one success, seven quota errors, 20 active keys. Multiple app processes require a database-atomic quota before scaling; no distributed framework was introduced.
- **F3:** subtraction-before-addition rejects ZIP size overflow; at most 256 entries and no duplicate normalized names. The eight cached official archives have 10–14 entries and parse with the new checks. Existing expanded-byte/row limits remain. No new CSV parser or speculative field limits; pathological CSV record allocation remains a documented residual concern.
- **S2:** archive URLs must be HTTPS on the official hostname/443 without userinfo. Redirects retain the initial HTTPS hostname/effective port and forbid URL credentials; Metro 8243 is preserved. At most two redirects; each followed request still consumes the existing upstream budget.
- **H1:** frame-ancestors 'none', DENY framing, host-only HTTPS HSTS and a narrow Permissions-Policy retain map geolocation. No broad script/style CSP or subdomain/preload policy.

The OpenAPI description documents the bounds/errors; generated Go and TypeScript artifacts still derive from that one spec. No response schemas or scope policies changed.
